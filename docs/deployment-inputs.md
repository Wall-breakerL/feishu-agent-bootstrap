## 通用新机清单

| 信息 | 需要提供什么 | 何时需要 |
|---|---|---|
| SSH 认证 | 可用 SSH alias / 本机私钥路径；或由部署 agent 生成专用公钥，用户通过 AutoDL 网页终端添加到服务器 authorized_keys | 进入服务器前；只有 hostname、port、user 不足以认证 |
| 代理 | 可供服务器使用的 Mihomo/Clash 完整配置文件路径，或存有订阅/节点的私密文件路径；说明是否允许复用现有配置 | 服务器直连模型服务不可用时；部署 agent 先检查已有代理 |
| 飞书机器人 | 已有应用的 App ID、App Secret 私密文件路径；或说明尚未创建。两种引擎建议分别创建应用 | 飞书联调前；用户需要有创建自建应用和发布版本的权限 |
| 飞书操作者 | 本人在各应用下的 open_id；不知道时由部署流程指导获取 | 启动可执行任务的 bridge 前；不能以手机号代替或开放通配符 |
| Claude Code API | 服务商、有效模型名、API key 私密文件路径；第三方服务的 Anthropic 兼容 endpoint | Claude API 路线联调前；没有时可先部署 Codex 路线 |
| Codex ChatGPT | 不提供密码；准备在自己浏览器中完成设备码/官方授权流程 | 代理和 CLI 准备好后再发起；无需提前生成短时验证码 |
| 工作项目 | 服务器已有项目绝对路径，或 Git URL + 分支/commit；私有仓库指出现有 Git 认证方式 | 未指定时先用独立测试目录验收，不动真实项目 |
| 历史与备份 | 是否已有旧机器人节点/会话要迁移；若有，提供状态备份私密路径并说明旧节点是否停止 | 迁移时必需；全新部署可先验证新会话的重启恢复 |

软件版本、代理端口、服务名称和安装目录可以由部署 agent 检查服务器后确定。它需要避开已有服务，记录所用版本，并分别测试 CLI、飞书收发、模型切换和会话恢复。

对 ChatGPT 登录，按 [OpenAI 官方 headless 认证说明](https://learn.chatgpt.com/docs/auth#login-on-headless-devices) 优先使用 `codex login --device-auth`；设备码功能需要账号/组织允许。必要的浏览器授权由用户本人完成。

## 本机私密材料位置示例

在项目仓库之外建立 `~/.config/feishu-agent-deploy/`（目录 700），将实际材料放入对应文件，文件权限设为 600。

```text
mihomo.yaml             用户自己的可用代理配置
api-bot.env             Claude API 机器人凭证、白名单与模型 key
codex-bot.env           Codex 机器人凭证与白名单，不含 OpenAI API key
```

环境文件格式参照 [bridge.env.example](../examples/bridge.env.example)，每个机器人一份；文件是可信 Bash 代码，仅使用本人维护的文件。聊天中只告知这些文件的绝对路径，部署时不回显内容。

## 记录部署进度

逐项记录 SSH、系统预检、代理、CLI 安装、认证、飞书收发、审批、模型切换、同会话重启和真实关机恢复的结果。哪一步还没通过，就停留在那个阶段。例如 SSH 尚未连通，只能说明本地材料已准备好。真实关机测试需要先确认没有必须保留的运行任务，并取得用户的停机授权。
