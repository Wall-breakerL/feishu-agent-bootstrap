| A1 | 目标身份 | 脱敏节点标识、SSH 主机指纹已核对、实际项目路径 |
| A2 | 版本与输入 | cc-connect/CLI 准确版本、profile、启动前检查通过 |

| A11 | 新实例切换 | 旧桥接退出，新实例启动后接单；恢复的项目 revision、结果及原生会话恢复核验一致 |
| A12 | 真实关机开机 | 代理 → 登录有效性 → bridge 顺序恢复；旧 session ID 与对话标记保持，记录自启或人工步骤 |

## 权限测试方法

使用专门测试目录和无价值的随机文件，不用真实研究结果做拒绝测试。

- `codex-readonly`：请求读取已知文件应成功，请求写入应被权限限制；它没有交互审批，不能要求在飞书弹审批才算通过。
- `codex-approval`：请求一个需要额外权限的测试写入，确认飞书出现审批并且批准后真实写入；第二次拒绝，核验目标文件没有产生。已有规则可能预先允许某些操作，需选择确实触发审批的测试动作。
- 文本审批必须等权限请求出现，再回复 `允许` / `拒绝`，或无斜杠的 `allow` / `deny`。`/allow` 是另一项工具预授权命令，Codex 不支持该命令；它不表示 Codex app-server 无法审批。首次验收不要选择“允许所有”。
- `claude-*`：默认权限与已有设置共同决定审批；核对规则后验证批准和拒绝。能够发文本回复不能代替工具调用验收。
- 卡片为可选增强；启用后对按钮再测一遍。纯文本审批失败也不能只以“聊天正常”放行。

## 故障恢复演练

首次使用某个版本组合，至少完成 A1—A8、A12—A13 及对应网络检查，才满足本项目的日常使用目标。跨 provider 或双引擎时加测 A14 / A15。长期任务使用前补 A9—A10。只有 A11 在真正不同实例上通过，才可以在 README 或回执里写“换机恢复已验证”。

重启的 bridge 不能保证恢复进行中的模型请求。先检查结果与状态再决定继续；可重复的只读查询与会造成副作用的写入/训练提交应区别处理。

## 本地离线检查能证明什么

仓库测试覆盖缺失/空白/通配符白名单、缺少凭证、错误版本、示例值、多行值、未知 profile、带空格的目录以及四个模板的限制默认值、私密运行文件不展开密钥、模型选择保留、额外 provider 缺密钥拒绝启动、项目名冲突拒绝；确保 `--check` 不启动桥接、不创建状态目录、不回显测试秘密。

它们不调用真实 cc-connect 或 agent，不发网络请求，不证明上游 CLI 协议兼容、飞书权限有效、模型 key 有效或 AutoDL 可用。
