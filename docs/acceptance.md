# 验收清单

每次部署都重新填写这张表，只将实际通过的项目标为 PASS。已有实例的测试结果见 [服务器操作记录](server-operations.md) 和 [Codex 验收记录](codex-server-validation.md)，不能直接套用到新服务器。

| ID | 检查 | 通过证据 |
|---|---|---|
| A1 | 目标身份 | 脱敏节点标识、SSH 主机指纹已核对、实际项目路径 |
| A2 | 版本与输入 | cc-connect/CLI 准确版本、profile、启动前检查通过 |
| A3 | 模型独立工作 | CLI 返回随机标记并读对测试文件；确认 provider 与认证来源 |
| A4 | 飞书往返 | 手机发标记，收到目标机读取的同一标记；事件与发送两向通过 |
| A5 | 用户限制 | 允许用户可用；如有授权测试账号，非白名单用户不能调用 agent；没有测试账号则标记该分项未实测 |
| A6 | 读写与审批 | 只读模板无法写；写入路线完成批准一次、拒绝一次及文件副作用核验 |
| A7 | SSH 断开 | 关闭 SSH 后手机仍可交互、后台任务仍有进度 |
| A8 | 桥接重启 | 停止并重启后核对同一 agent session ID，能续答只在聊天中提供的标记；从 STATE 新建只算降级恢复 |
| A9 | 长任务 | 独立任务有 ID、日志、退出码/状态；聊天重启不误判任务成功 |
| A10 | 外部备份 | 备份目标可实际读取，关键哈希一致，未提交文件得到处理 |
| A11 | 新实例切换 | 旧桥接退出，新实例启动后接单；恢复的项目 revision、结果及原生会话恢复核验一致 |
| A12 | 真实关机开机 | 代理 → 登录有效性 → bridge 顺序恢复；旧 session ID 与对话标记保持，记录自启或人工步骤 |
| A13 | 手机切模型 | `/model switch` 后实际模型可用，session ID 保留，重启后选择保留 |
| A14 | provider 边界 | 在测试对话切 provider，确认会话重置并用 STATE 交接，不把它宣称无缝切换 |
| A15 | 两种引擎 | 两个机器人分别确认认证来源、目标目录；历史各自保留，并发写入隔离 |
| A16 | 消息排版与交付 | 手机核对无提及摘要中的标题、列表、代码块和表格；下载 `.md` 内容一致；同话题简短提及能触发对端，且对端能读取报告，最后不再互相提及 |
| N1 到 N6 | 网络 | 完成 [代理文档](proxy.md) 对应检查；API 401 或登录状态不代替实际回复 |

## 权限测试方法

使用专门测试目录和无价值的随机文件，不用真实研究结果做拒绝测试。

- 使用 `codex-readonly` 时，请求读取已知文件应成功，请求写入应被权限限制；它没有交互审批，不能要求在飞书弹审批才算通过。
- 使用 `codex-approval` 时，请求一个需要额外权限的测试写入，确认飞书出现审批并且批准后真实写入；第二次拒绝，核验目标文件没有产生。已有规则可能预先允许某些操作，需选择确实触发审批的测试动作。
- 文本审批必须等权限请求出现，再回复 `允许` / `拒绝`，或无斜杠的 `allow` / `deny`。`/allow` 是另一项工具预授权命令，Codex 不支持该命令；它不表示 Codex app-server 无法审批。首次验收不要选择“允许所有”。
- 使用 `claude-*` 时，默认权限与已有设置共同决定审批；核对规则后验证批准和拒绝。能够发文本回复不能代替工具调用验收。
- 模板默认启用卡片；批准和拒绝按钮需实际点击并核对工具结果。按钮未验收前不能只以“聊天正常”放行；回退到文本时，在原话题中真实 @ 请求审批的机器人再回复。

## 故障恢复演练

首次使用某个版本组合，至少完成 A1 到 A8、A12 到 A13 及对应网络检查，才满足本项目的日常使用目标。跨 provider 或双引擎时加测 A14 / A15。长期任务使用前补 A9 到 A10。只有 A11 在真正不同实例上通过，才可以在 README 或回执里写“换机恢复已验证”。

重启的 bridge 不能保证恢复进行中的模型请求。先检查结果与状态再决定继续；可重复的只读查询与会造成副作用的写入/训练提交应区别处理。

## 本地离线检查能证明什么

离线测试主要检查两件事。输入不合要求时，启动脚本是否拒绝运行，包括白名单、凭证、版本、profile、项目名和目录等情况；生成运行配置后，是否保留权限限制、密钥占位符和模型选择。测试还会检查 `--check` 没有启动 bridge、创建状态目录或输出测试密钥。

它们不调用真实 cc-connect 或 agent，不发网络请求，不证明上游 CLI 协议兼容、飞书权限有效、模型 key 有效或 AutoDL 可用。
