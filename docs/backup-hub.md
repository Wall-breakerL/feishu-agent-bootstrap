# 用常驻服务器保存机器人备份

AutoDL 实例会更换，飞书应用可以继续用。我们增加了一台常驻腾讯云服务器，保存加密后的配置和会话快照。两个 agent 仍在当前 AutoDL 实例运行。

## 这次做了什么

2026-09-22，先完成一次 AutoDL 到 AutoDL 的迁移，核对了 697 个文件和 6 个 SQLite 数据库。随后在新实例暂停两个 bridge，保存最新状态，再恢复服务。第二份快照包含 554 个文件，两个机器人各有 6 个会话。

备份包含 Claude 和 Codex 原生会话、cc-connect 会话映射、模型与显示配置、API 和飞书凭证、Codex 登录状态、代理配置及两个测试工作目录。部署代码也随包保存。研究数据集、模型权重、训练环境和运行中的进程需另外处理。

在本机用 age 加密后，约 34 MB 的包经 SSH 上传到常驻服务器。我们核对云端 SHA-256，再下载解密，逐文件核验，并对恢复出的 6 个数据库执行 `quick_check`。检查全部通过后才更新 `latest`。回读期间遇到一次 SSH 中断，使用 rsync 续传完成。

随后在旧实例 SSH 不可用时，用这份备份恢复了第三个 AutoDL 实例。两个机器人均沿用原私聊会话 ID，正确复述旧节点信息并读取新机标记，用户与服务端核对通过。

## 以后按这个顺序换机

1. 等当前任务结束，暂停两个 bridge，确认原生 agent 不再写入会话。
2. 保存配置、会话和工作目录，生成文件摘要与版本清单。还要继续用旧机时，再恢复服务。
3. 加密快照，上传到备份站的临时目录。校验和回读成功后，保存为独立版本并更新 `latest`。
4. 新实例安装同版本工具，下载快照并解密。恢复时保留原来的 root 用户、项目名和绝对路径。
5. 确认旧节点已停止接收消息，再启动新机代理和两个 bridge。核对账号、沙箱与飞书连接。
6. 在原私聊中测试旧上下文和新机专属文件。只加载会话文件，不能代替实际续聊验收。

旧实例不可用时，可以恢复最后一份已完成的备份；快照之后的新增对话不会自动补回。当前采用手动备份，没有定时同步，也不在备份站运行这两个机器人。

## 备份与密钥放哪里

服务器上的目录结构如下。地址和登录凭证保存在本地私密文件中。

```text
/srv/feishu-agent-backups/
  snapshots/<时间与来源>/
    snapshot.tar.age
    metadata.json
    SHA256SUMS
    verification.json
    RECOVERY.md
  latest -> snapshots/<最近验证通过的版本>
```

本项目的 `secrets/tencent-hub/` 可保存 SSH 私钥、age 解密密钥及本地恢复说明。整个 `secrets/` 目录被 Git 忽略，私钥文件权限设为 `600`，目录为 `700`。提交前还要用 `git check-ignore` 和 `git ls-files secrets/` 确认没有跟踪这些文件。常驻服务器只保存加密包和加密公钥。

解密密钥原件保留在个人电脑，另存一份到个人密码管理器。换机时不会把腾讯云 SSH 私钥或备份解密密钥复制到 AutoDL；目前由本机完成 SSH 中转和解密，再把状态包传给新实例。

启动策略仍为手动接管。新机不自动安装开机钩子，旧实例开机后也不能自动抢接同一组飞书应用。完整迁移检查见 [迁移流程](migration.md)，本轮恢复结果见 [换机记录](server-migration-validation.md)。
