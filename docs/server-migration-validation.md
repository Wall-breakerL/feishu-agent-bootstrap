# 双机器人换机记录

2026-09-22，将 Server CC 和 Server Codex 从旧 AutoDL 实例切换到另一台实例。复用原飞书应用、群聊权限和白名单，保持项目名、OS 用户、绝对工作目录及工具版本一致。本次没有搬运研究项目的数据、训练环境或正在运行的实验。

## 切换过程

1. 新机先安装固定版本工具。复用官方安装包缓存，由安装器重新校验摘要：cc-connect 1.5.0、Claude Code 2.1.278、Codex 0.155.1、Mihomo 1.19.31；独立服务管理器使用 Supervisor 4.2.5。
2. 确认旧机两个 agent 空闲，备份并暂时停用旧机专用于 bot 的开机入口，再停止两个 bridge。旧机的其他服务没有随迁移停止。
3. 停写后打包私密配置、代理配置、两份 bridge 状态、Claude 项目会话、Codex 登录态及原生会话、两个测试工作目录。排除运行时 socket、临时目录和进程锁；包和逐文件 SHA-256 清单保存在仓库之外。
4. 经 SSH 传输，在新机逐文件核对 697 个文件，校验 Codex 的 6 个 SQLite 数据库。目标目录保留原绝对路径，未覆盖新机已有研究项目。
5. 启动新机代理，验证 Google 返回 HTTP 200；检查两条运行配置和 Codex 的 ChatGPT 登录状态，再验证 Codex 沙箱能读取测试文件、拒绝未批准的写入。
6. 新机手动启动两个 bridge。两边均建立飞书长连接，各载入 5 个旧会话；旧机两个 bridge 保持 STOPPED。

旧桥接在 13:20 左右停止，新机两条 bridge 在 13:23 左右上线，切换中断约 3 分钟。这只统计此次已准备好工具后的接管阶段，不包括安装包传输、环境准备和手机验收，不能当作任意新实例的部署时长保证。

## 当前证据

| 检查 | 结果 |
|---|---|
| 工具版本与官方安装包摘要 | 通过 |
| 697 个迁移文件 SHA-256 | 全部一致 |
| Codex 原生 SQLite 数据库 | 6 个 `quick_check` 均为 `ok` |

手机验收分别在两个机器人原来的私聊中进行：先要求模型复述上一轮重启验收标记，禁止读文件查历史；再读取只在新机生成的 `migration-node.txt`。服务端需核对原生会话 ID 与旧机一致、实际读取结果与新机随机标记一致，并确认模型完成本轮回复。

## 启动策略暂不定案

本次只处理接管所需的状态：旧机的 bot 开机入口已备份并暂时停用，新机尚未安装 bot 开机钩子。后续采用每次开机手动选择活跃节点，还是其他方式，另行讨论。不要直接在两台机器上恢复同一组 bot 的自动启动。

新机当前的手动恢复入口如下。执行前先确认旧机没有运行同一应用的 bridge。

```bash
cd /root/tools/feishu-agent-bootstrap
bash scripts/agentctl.sh start mihomo
bash scripts/agentctl.sh start api
bash scripts/agentctl.sh start codex
bash scripts/agentctl.sh status
```

需要回滚时，先停新机两个 bridge，再在旧机手动启动；旧机原始文件仍保留。若要保留切换后新增的对话，应在新机停写后将最新会话状态迁回，不能直接把旧快照当作最新状态。账号刷新后旧登录缓存也可能失效，需重新核对认证。
