# 给部署 agent 的可复用任务书

下面整段可复制到本地 Codex / Claude Code。它是一份执行规格，不声称单靠提示词就能保证部署成功。

---

请按照当前仓库的 docs/runbook.md，在我指定的新 Linux / AutoDL 实例上部署“飞书 ↔ cc-connect ↔ agent”工作流。先阅读 README、docs/research.md、docs/acceptance.md 和目标项目自身的 AGENTS.md / CLAUDE.md。

## 输入

- 目标 SSH alias，或 hostname / port / user：由用户提供。
- SSH 身份：优先使用本地已配置的密钥或 ssh-agent；交互密码由用户在安全终端输入。
- 目标项目仓库、分支或 commit、固定工作目录：由用户提供。
- 配置路线：claude-deepseek / codex-readonly / codex-approval / claude-anthropic。
- 模型认证：所有 API 使用 Claude Code；Codex 只用 ChatGPT 账号登录，优先设备码。
- 网络：用户提供的 Mihomo 订阅/节点私密文件；不要要求把订阅 URL 或节点密码发进聊天。
- 飞书应用：新建一次或复用已有 App ID；App Secret 从指定私密文件获取。
- 允许操作的用户：该应用对应的 open_id 白名单。
- 是否替换旧实例、旧实例是否仍在线：必须明确。
- 数据和结果的实例外保存位置、允许的任务范围与预算。

只询问缺失且阻塞执行的信息。已确认的偏好和授权不重复询问。不要让用户把账号密码、API key、App Secret 或 OAuth token 粘贴进聊天；使用文件路径、环境注入或用户交互登录。

## 顺序

1. 只读检查目标身份、系统、架构、目录、空间、当前进程、CLI 版本、systemd 可用性与必要网络；保存脱敏检查结果。确认没有连错实例。
2. 给出要用的 agent、认证路线、工作目录、启动方式和拟变更文件。只改本次部署目录；已有配置先备份再做最小合并，不覆盖项目文件或已有登录。
3. 固定 cc-connect v1.5.0。agent CLI 使用已验收版本；没有基线则选择官方版本，记录准确版本并标注待验收，不把 latest 当作可复现版本。不得从本文推定某个模型账号可用。
4. 按 docs/proxy.md 先准备并验证服务器代理，再独立验证 agent CLI：登录状态、最小模型回复、读取指定测试文件。失败先修这一层，不把错误归咎于飞书。
5. 配置单用户飞书应用和显式白名单；两种引擎同时运行时分别用两个 App ID / project / state，避免同时改同一工作目录。先跑启动检查；空白白名单、通配符、错误工作目录、缺失凭证时不得启动。
6. 若在切换实例，按迁移流程先停止旧桥接再启用新桥接。不要用两个独立客户端竞争同一个 App ID 的消息。
7. 使用首次生成后保留的私密运行配置，不在重启时覆盖 `/model` 的选择；前台验证飞书往返，再进入 tmux / 已验证的服务管理器。不要因为容器有 systemctl 命令就假定 systemd 可运行。默认不开放管理端口、不跳过全部权限、不启用 heartbeat。
8. 用户在手机端发送随机验收标记。验证能读项目；需要写入时批准一次小改动并核验文件；验证拒绝后没有副作用。发送测试消息属于本次联调范围，真实账号登录必须由用户完成必要交互。
9. 验证 SSH/本地电脑断开后可继续使用、桥接重启后的同一 session 恢复，以及实际关机开机后的代理/bridge/模型选择/历史恢复、后台任务日志和产物。关机操作按用户已给授权执行，尚未授权则将该验收标为待执行。迁移练习完成前，不标成换机验证通过。
10. 交付部署回执：主机脱敏标识、版本、模板、目录、认证方式、启动/停止方法、验收结果、备份位置、未完成项。回执不得含秘密；日志也需审查脱敏后分享。

## 工作边界

- 不自动租实例、付费、释放旧实例、发布代码或关闭主机。
- 不复制整个 home 到 Git；不在镜像里打包账号登录态。
- 不因为审批不工作就切到 yolo；具体权限策略由真实需求决定。
- 不自动重跑状态不明的实验。先查进程、任务 ID、日志、checkpoint 和已有结果。
- 若账号交互或飞书后台操作必须由用户完成，说明唯一需要用户执行的步骤，然后继续可独立进行的准备工作。
- 最终只将确实完成的检查标为 PASS，区分文档查证、本地检查、目标机验证和端到端验证。
